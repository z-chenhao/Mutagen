# Experiment 0008 — Difficulty-Calibrated Improvement Discrimination

Standalone experiment workspace (detached from the production
workspace via the empty `[workspace]` table in `Cargo.toml`). Nothing
here is a production API and nothing here is promoted to
`mutagen-core` / `mutagen-runtime` / `mutagen-cli`.

See `docs/experiments/0008-calibrated-improvement.md` for the full
pre-registered design and results.

## Question

Can a baseline-only, pre-registered difficulty-calibration procedure
create sufficient held-out headroom and informative paired outcomes for
the objective evaluator to detect a controlled robustness improvement
on a real stochastic model? (Experiment 0007 had 24 valid held-out
pairs but only 1 informative pair.)

## Design in one paragraph

Phase A runs baseline only: 3 registered task families × 5 stress
levels (a `DropFirstNWrites{key, count}` silent-drop ladder, S0..S4) ×
5 repetitions = 75 episodes, in a registered cyclic stress order. A
pure selection rule (S0 ≥ 4/5 sanity; select S1..S4 with 2/5–3/5
baseline success, min |rate−0.5|, lower stress on ties) freezes a
per-family difficulty manifest. Phase B then evaluates baseline vs the
frozen `candidate_repair` prompt on each selected family's two held-out
tasks (6 reps, alternating condition order) at the frozen selected
stress. The candidate prompt is hash-frozen before any model execution
and the selector structurally never sees candidate data.

## Commands

```sh
# Network-free: 15 component/design checks, including both verifiers on
# the deterministic synthetic datasets.
cargo run --manifest-path experiments/0008-calibrated-improvement/Cargo.toml -- self-test

# Phase A (75 baseline-only episodes). --code-commit is the calibration
# code-under-test commit (40-hex); --endpoint is optional (defaults to the
# redacted MUTAGEN_EXP_BASE_URL).
MUTAGEN_EXP_BASE_URL=http://127.0.0.1:8000/v1 MUTAGEN_EXP_MODEL=incoai/Qwen3.8-27B-Splash \
cargo run --release --manifest-path experiments/0008-calibrated-improvement/Cargo.toml \
  -- calibrate \
  --trajectories docs/experiments/artifacts/0008-calibration-trajectories.jsonl \
  --summary docs/experiments/artifacts/0008-calibration-summary.json \
  --selection experiments/0008-calibrated-improvement/selected-difficulty.json \
  --code-commit <40-hex SHA of the commit under test>

# Verify the calibration artifacts + frozen manifest.
cargo run --manifest-path experiments/0008-calibrated-improvement/Cargo.toml \
  -- verify-calibration \
  --trajectories docs/experiments/artifacts/0008-calibration-trajectories.jsonl \
  --summary docs/experiments/artifacts/0008-calibration-summary.json \
  --selection experiments/0008-calibrated-improvement/selected-difficulty.json

# Phase B (48 or 72 episodes, derived from the frozen manifest).
MUTAGEN_EXP_BASE_URL=http://127.0.0.1:8000/v1 MUTAGEN_EXP_MODEL=incoai/Qwen3.8-27B-Splash \
cargo run --release --manifest-path experiments/0008-calibrated-improvement/Cargo.toml \
  -- evaluate \
  --selection experiments/0008-calibrated-improvement/selected-difficulty.json \
  --trajectories docs/experiments/artifacts/0008-evaluation-trajectories.jsonl \
  --summary docs/experiments/artifacts/0008-evaluation-summary.json \
  --code-commit <final-evaluation 40-hex SHA>

# Verify the evaluation artifacts + summary + conclusion.
cargo run --manifest-path experiments/0008-calibrated-improvement/Cargo.toml \
  -- verify-evaluation \
  --selection experiments/0008-calibrated-improvement/selected-difficulty.json \
  --trajectories docs/experiments/artifacts/0008-evaluation-trajectories.jsonl \
  --summary docs/experiments/artifacts/0008-evaluation-summary.json
```

`calibrate`/`evaluate` refuse to run if `MUTAGEN_EXP_BASE_URL` /
`MUTAGEN_EXP_MODEL` are unset — no fallback model is substituted.

## Files

- `src/main.rs` — CLI (self-test / calibrate / evaluate / verifiers)
- `src/kernel.rs` — Rust-owned agent turn loop (12 turns / 16 calls)
- `src/model.rs` — one synchronous OpenAI-compatible client
- `src/protocol.rs` — chat protocol surface; usage is `null`-faithful
- `src/tools.rs` — `state_read` / `state_write` + `DropFirstNWrites` fault ladder
- `src/oracle.rs` — deterministic final-state task oracle
- `src/calibration.rs` — the pure baseline-only difficulty selector
- `src/stats.rs` — exact two-sided sign test
- `src/trace.rs` — records, summaries, gates, verifiers, synthetic data
- `src/experiment.rs` — orchestration + self-test
- `prompts/{baseline,repair}.md` — frozen before any model execution
- `tasks.json` — 9 registered tasks in 3 families (3 calibration / 6 held-out)
- `stress-levels.json` — registered S0..S4 ladder
- `selected-difficulty.json` — generated by `calibrate`, frozen before Phase B
